## 1. 実装したもの

```python
hits = await ai.search("怖い本を教えて", [b["desc"] for b in books], top_k=3)
# [{"index": 0, "score": 0.454, "text": "深夜の学校に…"}, …]  score の大きい順

vectors = await ai.embed([b["desc"] for b in books])   # list[list[float]]
question = await ai.embed("怖い本を教えて")             # list[float]
```

- `texts` が `str` なら1本、リストなら同じ順で返します
- `ai.load()` は不要。埋め込みは生成とは別のモデルとして、最初の呼び出しで読み込みます
- 教材ノートブック [`book_search.ipynb`](../notebooks/book_search.ipynb) も同梱しました（10冊の蔵書検索）

**モデルは `minilm` の1件のみ**、`EMBED_MODELS` という**チャットとは別の一覧**に置いています。
`ai.load("minilm")` は `ValueError` になり、`ai.models()` の一覧にも出ません
（ご了解いただいたとおりです）。

## 2. 契約に対して、library 側で行っていること

| 契約 | library 側 |
| --- | --- |
| 一度に 256 件まで | **超えたら自動で分けて複数回呼びます。** 素通しすると同じコードが PyHiroba で失敗し Colab で成功するため（600件 → 256/256/88 の3回で検証済み） |
| ベクトルは L2 正規化済み | **1本だけ長さを検算します。** 正規化されていないと内積がコサインにならず、近い順が静かに狂うためです。0.9〜1.1 の外なら理由を添えて止めます |
| 空の `texts` | 本体を呼ばずに `[]` を返します |
| reject の理由は日本語 | `_call_host` が包んで、そのまま利用者に見せます（従来は `JsException` のまま出ていました） |
| 目印で分岐 | `"ai-embed" in js.pyhirobaFeatures` で判定。無ければ「まだ文のベクトル化に対応していません」と伝えて**呼びません** |

`search()` は**質問と文書をまとめて1回**で投げます（別々だと橋を2往復するため）。

## 3. Colab 側の実装について（ご参考）

`sentence-transformers` は使わず、`transformers` + `torch` で mean pooling と
L2 正規化を自前で書きました。**本体と同じ手順を書いているので、両経路で同じ意味の
ベクトルになります。**

この平均プーリングは新しく書いた部分なので、**実数値で検証しました**。padding に
極端な値を入れておき、mask で除外できていなければ結果が大きくずれる形にしてあります。

    padding を含む2語の文 → 期待 [1.0, 0.0]   一致
    3語の文               → 期待 [0.0, 1.0]   一致
    ベクトルの長さ         → 1.0              一致

436 のテストが通り、変異テスト6件（padding を除かない／正規化しない／分割しない／
目印を見ない／検算しない／search が2往復する）は、いずれも対応するテストが落ちることを
確認しています。

## 4. ご確認いただきたいこと（1件）

### revision の記述が、いただいた文書の中で食い違っています

同じ文書の2箇所が逆のことを書かれています。

| 箇所 | 記述 |
| --- | --- |
| 「実装上の1点の訂正」 | SHA 固定は通信ガードに弾かれた。**`revision: 'main'` にしています** |
| §4 の表・注記 | **上記 revision（コミットID）に固定します**（配布元の差し替え防止） |

**どちらが実装でしょうか。**

厄介なのは、**いま両者が同じ挙動になる**ことです。こちらで確認したところ、
挙げていただいた SHA は現在の `main` そのものでした。

    main の現在の SHA: 2c4055b12046f11709e9df2c122e59ffbdc2f900
    §4 の SHA        : 2c4055b12046f11709e9df2c122e59ffbdc2f900   一致

つまり**実機で通ったことは、どちらであるかの証拠になりません**。差が出るのは
配布元に新しいコミットが入った瞬間 —「差し替え防止」が効くべき、まさにその場面だけです。

もし実態が `main` なら、§4 の「配布元の差し替え防止」は成り立っておらず、
THIRD-PARTY-LICENSES に SHA を書くと事実と違う記載になります。

また「transformers.js が config を `resolve/main/` で取りに行く」との記述からは、
**重みは SHA・config は main という部分固定**の可能性もあります。その場合は
「固定」と呼べないので、**どのファイルが固定されているのか**を明記いただくのが安全です。

**library 側の実装には影響しません**（revision は本体内部で解決され、こちらはキー
`minilm` しか渡さないため）。急ぎではありませんが、記録の正確さのためにご確認ください。

## 6. §7（同梱）へのご回答

**「0.5.2 の `host_supports()` で解消済み」というご理解で正しいです。** 0.5.0/0.5.1 は
`in_browser()`（＝`pyhirobaAsk` の有無）で判定しており、PyHiroba では常に真になるため
誤警告していました。0.5.2 で `pyhirobaFeatures` を見る形に変えてあります。

**0.4.0 → 0.6.0 の口を機械的に突き合わせました。**

| 項目 | 結果 |
| --- | --- |
| `get_form` / `pending_html` / `submit` | 同一 |
| `_REGISTRY_LIMIT`（64件） | 同一 |
| `Form.fragment`（`data-hui-*` を出す所） | **完全一致** |
| 投げる `kind` | 同一（`ai-load` / `ai-ask` / `ai-ask-start` / `ai-ask-next` / `ai-probe`）＋ `ai-embed` が追加 |

**差し替え＋版数書き換えだけで済む、というご認識どおりです。**

### ただし1点だけ、同梱前にご確認ください

0.5.1 以降、`Ai.__init__` が `threading.Lock()` を作ります。`ai = Ai()` はモジュール
読み込み時に走るため、**これは Pyodide でも実行されます**（Colab の ipywidgets 経路で、
ボタン押下から予約したタスクが走らない問題への対処です）。

Pyodide は `threading` を提供しており（使えないのは `Thread.start()` だけで `Lock` は
動きます）問題ないはずですが、**万一ここで落ちると `import library_hiroba` そのものが
失敗して全滅**します。開発サイトで最初に `import library_hiroba` だけ通していただければ
確実です。引っかかった場合は、遅延生成に変える小さな修正で対応します。

なお `threading` は `ui` 側の許可リストにも追加済みで、
[`PYHIROBA_INTEGRATION.md`](PYHIROBA_INTEGRATION.md) に経緯を記載しています。
