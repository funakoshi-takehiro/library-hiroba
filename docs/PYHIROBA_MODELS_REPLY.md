# ご返信：q4 に合わせました。そちらのバグ報告で、こちらの数字も3件間違いが見つかりました

対応ありがとうございます。**q4 を既定にする判断は妥当**だと思いましたので、
そのまま合わせました。加えて、そちらの「設計図ファイルだけを見ていた」という
報告を受けて**こちらの表も全モデル測り直したところ、3件ずれていて、
うち1件は不具合**でした。**0.7.1 として出します。**

---

## 1. `qwen35_08` は q4 を既定にしました

    browser_key:      qwen35_08-q4f16  →  qwen35_08-q4
    browser_variants: ("qwen35_08-q4", "qwen35_08-q4f16")   ← 順番も入れ替え
    approx_mb.browser: 469MB → 560MB

差が 81MB しかないのに、WebGPU の無い端末で ONNX Runtime の奥の読めない
エラーになる——という理由に納得しました。GIGA 第1期の iPad が対象に入るなら、
なおさらそちらを採るべきです。理由はコードのコメントにも残しました。

## 2. `qwen3_4b` は q4f16 のままにしています（ご意見をください）

こちらは `needs` で **WebGPU 必須**にしてあり、そもそも WebGPU の無い端末では
4B は実用になりません。そのうえ q4 にすると **3962MB**（q4f16 は 2890MB）で、
ただでさえ重いものが 1GB 増えます。そのため q4f16 のままにしました。

**ただし、そちらが 4B を q4 で ready にされるなら合わせます。** 既定の量子化が
食い違うと、同じ名前で落ちる大きさが環境ごとに変わってしまうので、
方針が決まりましたらお知らせください。

## 3. そちらの報告を受けて、こちらの表も測り直しました

**同じ誤りをしている疑いがあったため、全7モデルを測り直しました。**
外部データのファイル（`model_q4.onnx_data`、続きがあれば `_data_1` `_data_2` …）も
足して合計しています。**3件ずれていました。**

| モデル | 表の値 | 実測 | |
| --- | --- | --- | --- |
| `qwen05`（**既定**） | 900MB | **512MB** | 76% 多く言っていた |
| `qwen15` | 1600MB | 1788MB | 11% 少なく言っていた |
| `qwen3_17` | 1300MB | **2147MB** | **65% 少なく言っていた** |

### そのうち1件は不具合でした

`qwen3_17` は**空き容量の下限が 2000MB** なのに、**実サイズが 2147MB** でした。
空き容量 2000MB ちょうどの端末は**判定を通ってから、途中で足りなくなります**。
生徒には「なぜか進まない」としか見えません。2700MB に直し、
「空き容量の下限は配布サイズを下回らない」ことをテストで固定しました。

### 単位が混ざっていました — そちらの 2.7GB とこちらの 2.9GB は同じものです

測り直して分かったのですが、`qwen3_06` の 589 と `llmjp150m` の 255 は、
**MiB の値をそのまま MB として書いていました**（618MB = 589MiB、268MB = 256MiB）。
おそらく以前いただいた実測値をそのまま転記したためです。

そちらが 4B を「2.7GB」、こちらが「2.9GB」と書いているのも同じ理由です
（2890MB = 2.69GiB）。**こちらは 10 進の MB に統一しました**。校内の回線の話は
回線業者と同じ 10 進で数えるほうが、先生にとって確かめやすいためです。
そちらの表示と食い違うのは避けたいので、揃えるかどうかご相談させてください。

### 再発防止

`tools/check_model_sizes.py` を足しました。配布元と突き合わせて、ずれと
「空き容量の下限 < 実サイズ」を報告します。通信が要るので CI では回さず、
モデルを足したとき・上流が更新されたときに手で回す想定です。

## 4. 実機で確かめていただきたいことが1つできました

数字を直した結果、**`qwen3_06`（620MB）は `qwen05`（520MB）より大きい**ことが
分かりました。逆だと思っていました。

`qwen3_06` は「一覧でいちばん小さいから、メモリの少ない端末を救える」という
理由で、`needs` のメモリ条件をいちばん緩く（2GB）してあります。**その理由が
成り立たなくなりました。** ただし実際に 2GB の端末で動くかどうかは実機でしか
分からないので、**当てずっぽうで動かさず据え置き**、コメントに経緯を残しました。

低スペック機で試せる機会がありましたら、`qwen3_06` と `qwen05` のどちらが
2GB 級の端末で実用になるか教えていただけると助かります。
