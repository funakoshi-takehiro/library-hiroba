## §5：ご指摘のとおり、私の推測が誤りでした

**接頭辞なしで測られたのでは、という私の見立ては外れていました。** `e5prefix=true` で

そのうえで、いただいた数字から1点だけお伝えしたいことがあります。

### `top_k` は「関係の有無」を見ません

E5 の「スポーツ 0.818 がホラー 0.819 とほぼ同点」を、こちらは**順位の乱れ**と読んで
いましたが、いただいた MiniLM の実機結果を見ると、そうではありませんでした。

    MiniLM（実機・6冊）: 0.489 真夜中の校舎 / 0.386 旅館の怪談 / 0.341 青春サッカー

**MiniLM でも3件目はサッカーの本です。** 怖い本が2冊しかないところに `top_k=3` を
求めれば、3件目は必ず何かで埋まります。つまり「無関係な本が上位に入る」のは
モデルの優劣ではなく、`top_k` の性質でした。

両モデルの実質的な違いは**順位ではなく、スコアの離れ方**です。

| | 1位→3位の差 |
| --- | --- |
| MiniLM | 0.489 → 0.341（0.148） |
| E5 | 0.843 → 0.818（0.025） |

MiniLM を選ぶ理由は「**境目が数字で見える**」ことであって、E5 の順位が悪いから
ではない、というのが正確なところだと思います。E5 のスコアが密集するのは
ご指摘のとおり本来の性質で、接頭辞の有無とは別の話でした。この理解で合っていますか。

**教材側を直しました。** `book_search.ipynb` に、`top_k` は言われた数だけ返すこと・
`近さ` が急に下がったところが実質の境目であることを書きました。これを書いておかないと、
生徒が3件目を見て「壊れている」と受け取ります。**ノートブックは同梱の対象外なので、
すでに反映されています**（Colab から開けば新しいものになります）。

## §4：訂正ありがとうございます。1つだけ手を打ちました

**実態が `main`（何も固定していない）**と確定したこと、`THIRD-PARTY-LICENSES.md` から
SHA を消していただいたこと、了解しました。全チャットモデルも同じで、revision 固定は
共通の将来課題という整理も理解しました。

そのうえで、**固定されていないと「モデルが差し替わっても誰も気付かない」**のが唯一の
気がかりです。先生から見ると「前と結果が違う」だけで、原因にたどり着けません。

そこで **0.6.1 で、返ってきたベクトルの長さ（次元）を検算する**ようにしました。

    ベクトルの長さが変わっています（384 のはずが 768）。
    配布元のモデルが差し替わった可能性があります。

正規化の検算と同じ考えで、**静かに間違うより止まるほうがよい**という判断です。
本体側の対応は不要で、`dim: 384` を返し続けていただければ何も起きません。
もちろん次元が同じまま中身が変わる差し替えは捕まえられないので、**これは
revision 固定の代わりにはなりません**。気付ける範囲を少し広げるだけのものです。
