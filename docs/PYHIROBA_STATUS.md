## 3. 0.6.1 で直したこと

タグを打つ前に `embed` / `search` の一式を監査しました。探したのは「例外にならず、
それらしい答えが返ってしまう」書き方です。教材ではこれがいちばん困ります —
先生も生徒も、間違っていることに気付けません。**6件見つかりました。**

| # | 書き方 | 前（黙って間違う） | 後 |
| --- | --- | --- | --- |
| 1 | `ai.search("怖い本", "あいうえお")` | 5文字を5冊の本として検索 | `ValueError` |
| 2 | `ai.search(q, {"題名": "説明文"})` | 説明文を捨てて題名だけ検索 | `ValueError` |
| 3 | **本体のベクトルの検算** | **1本目しか見ていなかった** | **全件を検査** |
| 4 | `ai.embed(123)` | `'int' object is not iterable` | 読める文言 |
| 5 | 本体が壊れた値を返す | `could not convert string to float: '文'` | `RuntimeError` |
| 6 | 件数の上限なし | 100万件で 3907 往復してブラウザが落ちる | 10,000 件で停止 |

### 3番だけ、次の同梱で取り込んでいただくのがよいと思います

**これはこちらの実装の穴でした。** 前回お伝えした「次元の検算」は1本目だけを見ており、
途中から長さの違うベクトルが混じると素通りします。そのうえ内積が `zip` で短いほうに
切りそろえるため、**エラーにならず、近い順だけが静かに狂います**。

全ベクトルを検査し、内積も長さが違えば拒むようにしました。ほかの5件は書き間違いを
止めるだけなので、正しく書かれた教材の動きは変わりません。

もう1件、こちらの実装ミスがありました。埋め込みモデルの二重読み込みを防ぐ鍵に
**生成用の鍵を使い回して**おり、生成中に `embed()` を呼ぶとノートブックごと固まる状態
でした。鍵を分けてあります。

## 6. 0.8.0 について（本体側の対応は不要です）

全28機能を対象にバグ監査を行い、**14件**を直しました。契約は変えていません。
本体側に関わりうるのは次の2点です。

**1. 容器に入れたフォームが引き当てられるようになりました。** `ui.stack(card, form)`
のように容器へ入れると、`Form` の登録が走らず `ui.get_form(id)` が `None` を返して
いました。本体の worker は `form is None` なら黙って戻るため、**ボタンは描かれて
いるのに押しても何も起きない**状態でした。登録を `fragment()` に移して直しました。
本体側の変更は要りません。

**2. `ai.search()` に辞書のリストを渡すと止まるようになりました。**
`[{"title": …, "desc": …}, …]` は本の一覧でいちばん自然な形なのに、`str()` で
丸められて `"{'title': …}"` が丸ごとベクトル化されていました（例外にならないので
「なぜか結果がおかしい」とだけ見える形）。いまは読める文言で止めます。

ほかは `ui` 側の表示と検証、`talk` の履歴の並び、Colab 経路の挙動そろえです。

## 7. 本体側にお願いすること

- **`dim: 384` を返し続けていただければ、何も起きません。** `ai-embed` の契約は不変です
- 次の同梱を 0.6.1 に上げていただけると、上の3番が塞がります
- `ai-stream` はいつでも構いません
- **新規（0.9.2）: 既定のモデルが `qwen05-q8` から `llmjp150m-q4` に変わりました。**
  - **対応は要りません。**`llmjp150m-q4` は以前から一覧にあり、そちら側で実サイズを
    測っていただいた（255MiB＝268MB）モデルです。念のため、一覧に残っていることだけ
    ご確認ください。**ここが抜けていると、引数なしの `ai.load()` が全部失敗します**
  - 変えた理由：既定は**環境を調べずに読む**ところなので、**WebGPU を要らない唯一の
    モデル**にしました。Safari の WebGPU は iPadOS 26 以降でないと有効にならず、
    そこへ上げられない iPad では `qwen05` が読めていませんでした
  - 通信量は下がります（520MB → 270MB）。答えの質が要る場面は `ai.load("auto")` に
    回しており、そちらは端末のメモリが分かれば今までどおり上のモデルを選びます
  - **1つお願いが増えます：`ai-probe` で `memoryGB` を返せる端末では返してください。**
    返らないと、こちらは「分からない」として既定（＝いちばん軽い）までに抑えます。
    iPad の Safari は `navigator.deviceMemory` を持たないので、そこは抑えたままです
- **新規（0.9.1）: `sarashina05-q8` をブラウザ側のモデル一覧に足していただけますか。**
  - 配布元: `onnx-community/sarashina2.2-0.5b-instruct-v0.1-ONNX`（MIT）
  - 使うファイル: `onnx/model_quantized.onnx`（= `model_int8` / `model_uint8` と同じ 795MB）
  - **`q4` は 939MB で q8 より大きい**ので使いません。語彙が 102,400 あり、
    4bit 化の対象から外れる埋め込み層が効くためです
  - 急ぎません。足していただけるまで、こちらは Colab 経路でだけ動く扱いにしてあります
    （`ai.load("sarashina05")` はブラウザでは本体に断られます。断られたときに
    「もっと軽いものがある」と案内する文を 0.9.1 で足しました）
  - 国産で日本語がいちばん自然です。実機比較では、現行の小型4つが全て外した
    「光合成の仕組み」「敬語の言い換え」「富士山の標高と県」を、このモデルだけが
    正答しました。一方 `1500÷3` を 750 と答えるので、**おまかせには入れていません**

## 9. 0.9.0 について（本体側の対応は不要です）

生徒が1万人を超えたので、脆弱性・不具合・スマホ〜PC の崩れ・GIGA 端末での動作を
網羅的に監査しました。**契約（`kind` の受け渡し）は変えていません。** 直したのは
こちら側の10件です。変異テストで、1つずつ戻すと対応するテストが落ちることを確認済みです。

| # | 直したこと | 効き方 |
| --- | --- | --- |
| 1 | `as_texts()` が `None` 混じりの並びを素通りさせていた（番兵の既定値が `None`） | 埋め込みが意味の無いベクトルを作り、検索結果が静かに狂っていた |
| 2 | `clear_on_submit=True` で数値欄だけ消えていなかった | 1台を回して使う教室で、前の生徒の数値が混ざって送信される |
| 3 | `ui.table()` に行ごとに違うキーの辞書を渡すとセルが行数の2乗になっていた | 1000行で100万セル。GIGA 端末（3〜4GB）が描画で固まる |
| 4 | `ui.html()` のゲートが `<!-->` を見落としていた | そちらの DOMPurify が消すものを Colab で素通りさせ、**パリティの警告が機能していなかった** |
| 6 | `ui.html(css=)` のスコープを CSS ネストからセレクタ前置に変更 | ネスト未対応（iPadOS 15〜16.3 など）でユーザー CSS が1行も効かなかった |
| 7 | チャットの長い語が画面の左へ出て読めなくなっていた | 右にあふれないのでスクロールバーも出ず、先頭に到達できない |
| 8 | CSS 文字列中の生の改行でスコープの外へ漏れていた | **全セルが1つの document を共有するそちら側で影響が大きい** |
| 9 | `ui.columns(ui.stat(...))` が全画面幅で 8px はみ出していた | 常に横スクロールが出る |
| 10 | 入力欄が 15px でタップ領域が 37px だった | iOS がフォーカス時にページを自動拡大する／指で押しにくい |
| 11 | 版の食い違いの知らせがフォームにしか出ていなかった | `ui.card` だけ使う生徒は、直らない画面を見ながら何も知らされなかった |

### 6 と 8 についての補足（表示に関わるので念のため）

`ui.html(css=...)` が出す CSS の**形**が変わりました。中身の効き方は同じです。

```
旧: .hui-raw-xxxx { b { color: red } }      ← CSS ネスト
新: .hui-raw-xxxx b { color: red }          ← セレクタ前置
```

モダンブラウザでの描画が同じであることは、教材 `html_css_recipes.ipynb` の実 CSS 9件で
計算済みスタイルを全要素ぶん突き合わせて確認しました（差分 0 件）。
`@media` の中も前置します。`@import` はスコープに閉じ込められないので落とします。

### 修正そのものを監査して、さらに直した分

10件を入れたあと、その修正が新たな不具合を作っていないかを敵対的に見直しました。
**8件見つかり、すべて直してあります。** 主なものは下の2つで、どちらも `ui.html(css=)` の
スコープに関わるので、全セルが1つの document を共有するそちら側では影響が大きいものでした。

- **セレクタの中のエスケープ（`.a\" {`）で、次のルールがページ全体に効いていた。**
  CSS の字句解析が「文字列の外の `\` エスケープ」を扱っていなかったため、幻の文字列が
  開いて切り出しがずれていました。ブラウザ実測でスコープ外の要素に効くことを確認しています。
  併せて `url(ken's.png)`（引用符を含む引用符なし url）も扱えるようにし、
  以前は正当なのに拒否していたものが書けるようになりました。
- **`<![CDATA[>` でゲートがすり抜けていた**（こちらは今回の修正が原因ではなく、以前から）。
  HTML では `<![` は「最初の `>` で終わる偽コメント」ですが、Python の HTMLParser は
  `]]>` を探すため食い違います。`tools/check_parser_parity.py` を22ケースに広げ、
  「ブラウザが動かすのに検知できない」ものが無いことを確かめました。

ほかに、入力の誤りで弾かれたときに原因の値まで消えていた点、失敗した押下が走っている
答えを打ち切っていた点、表の列数上限が正当な幅広い表（30行×365列など）まで巻き込んで
いた点、版ずれの知らせがフォームで2枚並んでいた点、同時に描いたときに人数ぶん出ていた
点、壊れた配布情報で「None が入っています」と出ていた点を直しました。

変異テストは25件すべてが「戻すと対応テストが落ちる」ことを確認済みです。

### 5 は保留です（モデルの必要メモリ）

`MODELS` の `needs` に、大きさと要求メモリの逆転があります（520MB のモデルが 4GB 要求、
620MB のモデルが 2GB 要求）。さらに `_unmet()` は `memory is not None and ...` と
書かれているため、**メモリを測れない端末では条件がスキップされて「足りている」と判定**
されます。`navigator.deviceMemory` は Chrome 系だけなので、iPad では常にそうなります。

数字を直すには実機の測定が要るため、この版では触っていません。そちらで
`ai-probe` が iPad で何を返しているか分かれば教えてください。
