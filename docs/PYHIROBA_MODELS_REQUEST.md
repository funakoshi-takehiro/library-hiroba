## なぜこの2つか

### `qwen35_08` — いちばんの収穫です

**いま既定にしている `qwen05`（900MB）より軽い 469MB で、2世代新しい**モデルです。
低スペック機を救うために入れた `qwen3_06`（589MB）よりも軽くなります。

Colab 側（`Qwen/Qwen3.5-0.8B`）で実際に読んで確かめました。

    読み込み 12.4 秒（CPU）
    Q: 日本で一番高い山は？20字以内で。   A: 富士山
    Q: 水が氷になる温度は？              A: 0℃です（以下、理由の説明が続く）

0.8B としては日本語がかなり良いです。1点だけ、「氷点」を「冰点」と中国語の字で
書くことがありました。教材で使う際の注意点として共有します。

### `qwen3_4b` — 「もっと賢い」への答えですが、既定にはしません

ブラウザで動く上限がここです。ただし **2.9GB を生徒一人ひとりが落とす**ことになり、
40人学級なら 116GB です。そのため `ai.load("auto")` でも `await ai.recommend()` でも
**選ばれないように**してあります（先生が名前を書いたときだけ動きます）。この判断は
教室の回線を知っている人がするべきで、こちらが自動で決めてよい話ではないためです。

## 調べて「できない」と分かったこと

ご参考まで。`docs/PYHIROBA_INTEGRATION.md` の記述より状況が進んでいる部分があります。

| 候補 | 結果 |
| --- | --- |
| **Qwen3 8B** | ONNX はありますが **ONNX Runtime GenAI 形式のみ**で、transformers.js の `onnx/model*.onnx` 配置ではありません。読めません |
| **Qwen3.5 の 2B / 4B** | 公開されているのは画像つき（VL）版だけです。テキスト版は 0.8B のみ |
| **LLM-jp の 150M より大きいもの** | **全 author を調べて、ONNX は 150M しかありません**（instruct2 と instruct3 の2つ）。440M・980M・1.8B・3.7B、および新しい llm-jp-4（8B・33B）には変換版がありません |

LLM-jp については、**150M の instruct3 の ONNX が新しく出ています**
（`onnx-community/llm-jp-3-150m-instruct3-ONNX`）。いまこちらは instruct2 を
使っていますが、これは以前 instruct2 しか ONNX が無かったためです。150M では
両者の差はほとんど無いと見ているので、**こちらからは切り替えていません**。
そちらで instruct3 に寄せたいご事情があれば合わせます。

## `Qwen3.5-0.8B-Text-ONNX` の `-Text` について

本家 `Qwen/Qwen3.5-0.8B` は画像の設定も持つ形（`model_type: qwen3_5`）で、
ONNX 側はそのテキスト塔だけ（`qwen3_5_text`）です。名前が違うので、
**同じモデルかどうかを実際に突き合わせました。**

- `hidden_size` / `num_hidden_layers` / `num_attention_heads` / `num_key_value_heads` /
  `intermediate_size` / `vocab_size` / `max_position_embeddings` / `rms_norm_eps` の
  **8項目すべて一致**
- **チャットテンプレートが 7755 文字で完全一致**（sha256 `273d8e0e683b8850…`）

文章しか扱わない用途では同じ重みを見ている、と判断しました。Colab 側では
`pipeline("text-generation")` が `Qwen3_5ForCausalLM` を作り、実際に動いています。
